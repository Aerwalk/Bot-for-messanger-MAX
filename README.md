# «Спорт рядом» — MVP бота для MAX

**Трек хакатона:** «Досуг и развлечения».

**Назначение решения:** помочь жителю города найти подходящую спортивную активность рядом (секция, площадка, тренировка, соревнование), увидеть живое расписание с реальным числом свободных мест, тренера с рейтингом и завершить запись на занятие — полностью внутри мессенджера MAX, в чате с ботом.

---

## 1. Целевая аудитория

- **Основной сегмент (MVP):** взрослые 25–45 лет с занятостью (работа, семья), которые хотят тренироваться рядом с домом или работой и ценят близость, понятное расписание, цену и быструю запись.
- Будущие направления: родители с детьми (секции 6+), студенты (бюджетные тренировки), начинающие спортсмены (уровень подготовки).

## 2. Проблема

Пользователь хочет начать регулярно заниматься спортом, но путь до **подтверждённой записи** — вручную: поиск по сайтам и соцсетям, сверка расписаний и цен, переписка с организатором, неизвестность про свободные места. В результате он тратит много времени, сомневается в актуальности информации и часто бросает на этапе «собрания информации».

**Core job:** «Я хочу за 1–2 минуты найти ближайшую подходящую активность и сразу получить подтверждённую запись».

## 3. As Is (текущий путь)

| Шаг | Действие пользователя | Источник | Боль |
|---|---|---|---|
| 1 | Понял, что хочет заниматься спортом | — | Нет единой точки входа |
| 2 | Ищет секции/площадки | Поисковики, соцсети, сайты | Информация разрознена |
| 3 | Сверяет расписание | Сайт/группа организатора | Часто устарело |
| 4 | Уточняет адрес и дистанцию | Карты | Нужно открывать ещё одно приложение |
| 5 | Выясняет цену, возраст, уровень | Переписка/сайт | Долго, ответа может не быть |
| 6 | Узнаёт про свободные места | Звонок/сообщение | Никакой прозрачности |
| 7 | Регистрируется | Форма на сайте/сообщение | Снова выходит из мессенджера |
| 8 | Получает подтверждение | Часто не получает | Нет уверенности |
| 9 | Сохраняет дату/время | Вручную в календарь/заметки | Легко забыть |

**Самая болезненная точка:** шаги 2–6 — сбор и сопоставление информации из разных источников при полной непрозрачности свободных мест.

## 4. To Be (целевой путь)

Пользователь **открывает чат-бота MAX → выбирает фильтры (вид спорта, день, время, радиус) → получает список подходящих вариантов рядом → открывает карточку → видит расписание и доступность → регистрируется → получает подтверждение → сохраняет/получает напоминание.**

| Что изменилось | Результат |
|---|---|
| Исчез ручной сбор информации из разных источников | Один каталог с живыми слотами |
| Исчезла необходимость уточнять свободные места | Число свободных мест видно сразу |
| Сократилась регистрация до пары нажатий | Имя + согласие, телефон не обязателен |
| Появилось подтверждение | Статус записи доступен в «Моих записях» |
| Появилось напоминание из бота | Не нужно запоминать дату/время |

**Итоговый результат сценария:** подтверждённая запись на конкретное занятие + напоминание от бота.

## 5. Продуктовая гипотеза

> Если показать пользователю рядом активности с живыми слотами (число свободных мест) и позволить записаться в 2 шага внутри MAX, то доля пользователей, дошедших до подтверждённой записи, будет заметно выше, чем в модели «напишите организатору» — потому что пропадает главное трение: сбор информации и неизвестность про доступность.

**Статус:** это гипотеза, а не подтверждённый факт. Проверяется на пилоте метрикой конверсии в запись.

## 6. Ключевая ценность и метрики MVP

Ценность: **«Найти подходящую спортивную активность рядом и записаться на неё за несколько шагов».**

| Метрика | Как измеряется |
|---|---|
| Conversion to result | `results_viewed` / `miniapp_opened` (события) |
| Conversion to registration | `registration_completed` / `results_viewed` |
| Completion rate | доля полностью завершивших сценарий до подтверждения |
| Time to registration | время от старта до записи (демо-замер) |
| Error rate | `registration_failed` + ошибки API / успешные операции |
| Repeat usage | повторные `miniapp_opened` одним пользователем |

На этапе хакатона показатели — гипотезы эффекта, а не фактические результаты.

## 7. Скоуп MVP (Must / Should / Could / Won't)

| Must Have | Should Have | Could Have | Won’t Have |
|---|---|---|---|
| Поиск по спорту/району/времени | Избранное | Рейтинги/отзывы (реализовано) | Онлайн-оплата |
| Карточка с расписанием и местами | Профиль с предпочтениями и гео | Свой гео вместо точки по умолчанию (реализовано) | Пуш-уведомления вне MAX |
| Запись на слот + согласие | Напоминания из бота | Подписка на новые слоты | Мультиязычность |
| Мои записи + отмена | Аналитика событий | Детский фильтр от 6 лет | Рекомендации на ML |
| Вход через MAX (initData) | Админ-панель организатора | Маршрут до объекта (Яндекс Карты) | AI-тренер |
| Оценки занятия и тренера | | | Интеграции со всеми внешними сервисами |

## 8. Основной пользовательский сценарий

1. Пользователь открывает чат-бота и нажимает «Поиск» (либо команду `/search`).
2. Указывает предпочтения: вид спорта, день, время, радиус (при желании — свою геолокацию).
3. Получает список вариантов рядом (карточки с тренерами, рейтингами и оценками).
4. Открывает карточку: описание, адрес, расписание, свободные места.
5. Выбирает слот и нажимает «Записаться».
6. Подтверждает запись (имя + согласие).
7. Получает подтверждение записи (+ кнопка «Построить маршрут»).
8. Переходит в «Мои записи» / отменяет запись при необходимости; прошедшие занятия можно оценить.
9. Бот присылает напоминание за 3 часа до занятия.

## 9. Состав компонентов

| Компонент | Папка | Стек | Назначение |
|---|---|---|---|
| Backend | `backend/app/` | **Python 3.12 + FastAPI + uvicorn** | REST API `/api/*`, PostgreSQL (SQLAlchemy), доменная логика, валидация initData (HMAC-SHA256), админка организаторов `/api/admin/*` |
| PostgreSQL | `db` (compose) | postgres:16-alpine | Хранение данных: спорт, объекты, активности, расписание, записи, пользователи, организаторы |
| Общие типы/константы | `shared/` | TypeScript (только типы) | Схемы данных, виды спорта, фильтры, этикетки |
| Чат-бот | `bot/` | TypeScript + `@maxhub/max-bot-api` | Связка с MAX: `/start`, поиск, карточки, запись, «Мои записи», избранное, профиль, напоминания |
| Админ-панель организатора | `admin-app/` | React + Vite + TypeScript | Вход организатора, создание/редактирование мероприятий и расписания |
| Документация | `docs/` | Markdown / OpenAPI | Продукт, API, тест-план, презентация, ревью |

> **Граница языков:** вся бизнес-логика и бэкенд — **Python**. TypeScript используется
> **только** там, где это требует MAX: чат-бот (`@maxhub/max-bot-api`) и админ-панель.
> Бот и админка общаются с Python-бэкендом по HTTP `/api/*`; серверных JS/TS-модулей в `backend/` нет
> (подробнее — `docs/review.md`).

## 10. Архитектура

```
MAX
 └── Bot (TS) ──────▶  Backend:8080 /api  ──▶  PostgreSQL (db:5432)
Organizer SPA (React) ──▶  /api/admin  ─┘
```

- **Bot** (TS) — старт, поиск, карточки, расписание, регистрация, избранное, профиль, напоминания.
- **Backend** (Python/FastAPI) — объекты, активности, расписание, регистрации, пользователи, статусы, аналитика, JWT-авторизация организаторов.
- **Admin SPA** (React/Vite) — вход организатора, CRUD мероприятий и слотов через `/api/admin/*`, раздаётся nginx на `:8081` с проксированием API.
- **Data layer** — PostgreSQL (SQLAlchemy 2.0); схемы создаются автоматически при старте, демо-данные сидируются при первом запуске.

## 11. Быстрый старт (локально)

Требования: **Node ≥ 20**, **Python 3.12** и **PostgreSQL 16** (или Docker для БД). При полном запуске через Docker БД поднимается автоматически.

```bash
# 1. Зависимости JS (shared, bot, admin)
npm install

# 2. Python-окружение для бэкенда
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # Linux/macOS
pip install -r backend/requirements.txt

# 3. Поднять БД (или использовать локальный PostgreSQL и поправить DATABASE_URL)
docker compose up -d db

# 4. Запуск бэкенда (API + админка), http://localhost:8080
npm run start:backend

# 5. Запуск бота (в отдельном терминале, с токеном)
npm run start:bot
```

При первом старте бэкенд создаёт схему в PostgreSQL и сидирует демо-данные: 8 видов спорта, 10 объектов, 12 активностей, расписание на 7 дней (есть заполненный и отменённый слоты для edge-кейсов) и организатора `admin`/`admin123`.

Для разработки бота и админки с перезагрузкой:

```bash
npm run dev:backend   # терминал 1
npm run dev:bot       # терминал 2
npm run dev:admin     # терминал 3 → http://localhost:5174 (проксирует /api на :8080)
```

### Порядок запуска (итого)

1. `npm install`
2. `python -m venv .venv && pip install -r backend/requirements.txt`
3. `docker compose up -d db` (либо свой PostgreSQL)
4. `npm run start:backend`
5. `npm run start:bot` (с токеном `MAX_BOT_TOKEN`)

## 12. Docker

**Одна команда запускает все четыре компонента:**

```bash
docker compose up -d --build
```

- `db` — PostgreSQL 16 на внутреннем адресе `db:5432` (healthcheck `pg_isready`).
- `backend` — FastAPI на `:8080`, ждёт здоровую БД, мигрирует схему и сидирует демо-данные. Данные в volume `sport-nearby-pgdata`.
- `admin` — nginx раздаёт собранный SPA на `:8081` и проксирует `/api` на backend.
- `bot` — бот; при пустом `MAX_BOT_TOKEN` работает в режиме ожидания.

Образ backend — python:3.12-slim (uvicorn). Образ bot и admin собираются из TypeScript (node:22-slim).

Логи: `docker compose logs -f backend`.

## 14. Используемые порты

- `8080` — backend (API + `/api/admin`).
- `8081` — админ-панель организатора (nginx/SPA).

## 16. Внешние сервисы и интеграции

- **MAX**: бот использует `@maxhub/max-bot-api` (актуальный официальный SDK).
- Валидация initData: HMAC-SHA256 (ключ `"WebAppData"`, данные + токен бота).
- **Других внешних интеграций нет** — все данные демонстрационные.

## 17. Источники данных

Данные **демонстрационные** (модельные), источник — `"Демонстрационные данные MVP"`. У каждого объекта и активности заполнены поля `source` и `sourceUpdatedAt`; на карточках это отображается пользователю.

Реальные интеграции, которые надо подключить после MVP: Единый календарный план Минспорта, реестры объектов спорта, данные организаторов — при этом источник и дата обновления остаются обязательными.

## 18. Тестовые данные

Создаются автоматически при первом старте (или командой `npm run seed:backend`):

- 8 видов спорта: футбол, баскетбол, плавание, теннис, бег, йога, волейбол, фитнес;
- 10 спортивных объектов с ценами, разными уровнями и возрастными категориями;
- 12 активностей: секции, площадки, тренировки, соревнования;
- расписание на 7 дней: слоты с местами, заполненный слот, отменённый слот, слоты разных цен.

Обновление дат относительно текущей даты (`npm run seed:backend`).

## 21. Интеграция с MAX и демо-сценарий

- Вход: бот идентифицирует пользователя через `x-user-id` (demo) или подтверждённый `initData` на `POST /api/me`.
- Бот: `/start` и событие `bot_started` → приветствие + меню; `/search`, `/popular`, `/my`, `/favorites`, `/profile`, `/help`; пошаговый поиск и карточки с регистрацией; опрос `GET /api/reminders/due` и рассылка напоминаний через `sendMessageToUser`.

**Пошаговый сценарий проверки (для жюри):**
1. Открыть чат-бота, нажать /start (или «Поиск»).
2. Выбрать вид спорта → день → время → радиус.
3. В списке открыть карточку активности (кнопки: дата/время/свободные места, фильтр «Только со свободными местами»).
4. Выбрать открытый слот → «Записаться» → подтвердить. В подтверждении — количество свободных мест, кнопка «Построить маршрут» (Яндекс Карты) и «Скопировать координаты».
5. Увидеть подтверждение записи.
6. Открыть «Мои записи» — запись на месте, её можно отменить.

**Ожидаемый результат:** пользователь находит подходящий вариант, выбирает конкретное занятие и получает подтверждение регистрации — без выхода из MAX.

### Админка организатора

Отдельная веб-панель для организаторов на `http://localhost:8081` (демо-вход: `admin` / `admin123`). Возможности:

- просмотр и управление мероприятиями (CRUD);
- создание расписания (слоты с датой, временем, вместимостью, тренером);
- мониторинг записей (заполненные слоты видны по числу `registeredCount`).

Авторизация — opaque-токен сессии (`POST /api/admin/login`), доступ к `/api/admin/*` только с валидным Bearer-токеном (хранится в БД `admin_sessions`, без JWT-подписи). Демо-организатор создаётся автоматически при первом старте бэкенда.

## 22. Известные ограничения MVP

- Все данные демонстрационные, live-провайдеров нет (источник «Демонстрационные данные MVP»).
- Нет оплаты; поиск идёт от точки по умолчанию — центр Москвы (если пользователь не указал геолокацию).
- Смена имени/аватара бота — только через интерфейс платформы MAX (SDK таких методов не даёт).
- Напоминания доставляются только если бот успел зафиксировать связь пользователь → чат (периодический аудит).
- Реальная регистрация бота в MAX не выполнена (требуют токен и публикацию) — код готов, но запуск в MAX требует валидных учётных данных.
- Геолокация мини-приложения использует `navigator.geolocation` (в MAX-bridge метода запроса геопозиции нет), поэтому требует HTTPS при публикации; демо гео в боте — через `requestGeoLocation` в профиле.
- Документация и UML-диаграммы: `docs/product.md`, `docs/presentation.md`, `docs/test-plan.md`, `docs/review.md`, `docs/master-check.md`, `docs/uml/*.puml`.

## 23. Остановка и повторный запуск

```bash
docker compose down            # остановить и удалить контейнеры (volume сохраняется)
docker compose down -v         # + сбросить данные
docker compose up -d           # повторный запуск (собранные образы переиспользуются)
```

Локально: `Ctrl+C` в терминалах; повторно — `npm run start:backend` и др.
