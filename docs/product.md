# Продуктовый паспорт MVP «Спорт рядом»

## 1. Проблема

У взрослого (25–45 лет, работа, семья) есть намерение заниматься спортом рядом с домом,
но путь к первой **подтверждённой записи** — ручной и длинный: поиск по сайтам и группам,
сверка расписания и цен, переписка с организатором, неизвестность про свободные места.

Пользователь теряет мотивацию на этапе «собрания информации». Конверсия из «захотел» в «записался» низкая.

**Core job:** «Я хочу за 1–2 минуты найти ближайшую подходящую активность и сразу получить
подтверждённую запись».

## 2. As Is (текущий путь)

| Шаг | Действие пользователя | Источник | Время/ручные действия | Боль и неопределённость |
|---|---|---|---|---|
| 1 | Понял, что хочет заниматься | — | — | Нет точки входа |
| 2 | Ищет секции/площадки | Поисковик, соцсети, сайты | ~30–60 мин | Информация разрознена |
| 3 | Сверяет расписание | Сайт/группа организатора | Переписка | Часто устарело |
| 4 | Уточняет адрес/дистанцию | Карты | Отдельное приложение | Нужно сопоставлять |
| 5 | Выясняет цену, возраст, уровень | Переписка/сайт | Ожидание ответа | Могут не ответить |
| 6 | Узнаёт про свободные места | Звонок/сообщение | Ожидание | Никакой прозрачности |
| 7 | Регистрируется | Форма/сообщение | Заполнение | Выходит из мессенджера |
| 8 | Получает подтверждение | Часто не получает | — | Нет уверенности |
| 9 | Сохраняет дату/время | Вручную в календарь | Ручной перенос | Легко забыть |

**Самая болезненная точка:** шаги 2–6 — сбор и сопоставление информации из разных источников
при полной непрозрачности свободных мест; пользователь часто отказывается от сценария именно здесь.

## 3. To Be (целевой путь)

Пользователь открывает чат-бота MAX → запускает мини-приложение → указывает предпочтения →
получает список подходящих вариантов рядом → фильтрует → выбирает вариант → видит расписание и
доступность → регистрируется → получает подтверждение → сохраняет/получает напоминание.

| Изменение | Результат |
|---|---|
| Исчез ручной сбор расписаний/цен/адресов | Один каталог с живыми данными |
| Исчезла переписка с организатором | Запись без участия организатора |
| Появилась прозрачность мест | Число свободных мест видно сразу |
| Регистрация сокращена до пары нажатий | Имя + согласие, телефон не обязателен |
| Появилось подтверждение | Статус в «Моих записях» |
| Появилось напоминание из бота | Автоматически за 3 часа |

**Завершение сценария:** получено подтверждение регистрации на конкретное занятие рядом
(и сохранено напоминание). Именно этот результат — критерий успеха.

## 4. Ценность

Запись на спорт рядом становится такой же простой, как заказ такси или доставки:
выбор из готовых слотов с реальным числом свободных мест, регистрация в пару нажатий
внутри MAX (без выхода из мессенджера), напоминание из бота.

Метрика ценности (KPI пилота): конверсия подтвёрждённая запись / поиск.

## 5. Сегмент (MVP)

- Взрослые 25–45 лет, желающие тренироваться рядом с домом/работой.
- Приоритеты: близость, подходящее время, цена, понятное расписание, подтверждение.
- Сравнение альтернативных сегментов (критерии: частота проблемы, боль, реализуемость MVP,
  полнота сценария в MAX, измеримость): взрослый «для себя» выбран как основной; родитель с
  детьми, студент, искатель соревнований — будущие направления.

## 6. Гипотеза MVP

> Если показать рядом активности с живыми слотами (свободные места) и позволить
> записаться в 2 шага внутри MAX, то доля пользователей, дошедших до подтверждённой записи,
> будет заметно выше, чем в моделях «напишите организатору» — потому что исчезает главное
> трение (сбор информации и неизвестность про доступность).

**Статус гипотезы:** не подтверждена фактами; проверяется метриками на пилоте.

## 7. Метрики успеха (пилот)

| Метрика | Определение |
|---|---|
| Conversion to result | `results_viewed` / `miniapp_opened` |
| Conversion to registration | `registration_completed` / `results_viewed` |
| Completion rate | полностью завершившие сценарий / стартовавшие |
| Time to registration | время от открытия мини-приложения до записи |
| Error rate | ошибки (в т.ч. `registration_failed`) / операции |
| Repeat usage | повторные визиты пользователя |

События пишутся автоматически в `/api/events` (`bot_started`, `miniapp_opened`,
`search_started`, `filter_applied`, `results_viewed`, `activity_opened`, `schedule_opened`,
`registration_started`, `registration_completed`, `registration_failed`,
`registration_cancelled`, `favorite_added`, `reminder_enabled`).

## 8. Скоуп MVP

| Must | Should | Could | Won't |
|---|---|---|---|---|
| Поиск по спорту/району/времени | Избранное | Рейтинги/отзывы (реализовано) | Онлайн-оплата |
| Карточка с расписанием и местами | Профиль с предпочтениями | Свой гео вместо точки по умолчанию (реализовано) | Пуш-уведомления вне MAX |
| Запись на слот + согласие | Напоминания из бота | Подписка на новые слоты | Мультиязычность |
| Мои записи + отмена | Аналитика событий | Детский фильтр от 6 лет | Рекомендации на ML |
| Вход через MAX (initData) | Управление тренерами (админка) | Маршрут до объекта (Яндекс Карты) | AI-тренер |
| Оценки занятия и тренера | | | |

## 9. Пользовательский путь (бот + 4 экрана мини-приложения)

1. **Бот:** `/start` → приветствие и кнопка «Найти спорт рядом» (web app).
2. **Поиск (мини-приложение):** фильтры (вид спорта, день, время, радиус, район) → результаты.
3. **Карточка:** описание, адрес, дистанция, оценка занятия, тренер и его рейтинг, расписание;
   на открытом слоте — «Записаться».
4. **Форма:** имя, телефон (необязательно), согласие → подтверждение.
5. **Успех:** карточка записи + «Мои записи» + «Напоминание» + кнопка «Построить маршрут»
   (Яндекс Карты). Бот пришлёт напоминание за 3 часа.
6. **Мои записи:** будущие и отменённые; можно отменить запись; для прошедших занятий —
   оставить оценку (тренировка 1–5, тренер 1–5, комментарий).

## 10. Информационная архитектура и UX/UI

Разделы: **Главная** (поиск + быстрые фильтры), **Результаты**, **Карточка активности**,
**Форма записи**, **Успех**, **Мои записи**, **Профиль** (предпочтения, геолокация). Навигация —
нижние табы «Поиск» / «Мои записи» / «Профиль»; внутри — простые CTA и отсутствие тупиков.

Геолокация: мини-приложение запрашивает координаты через `navigator.geolocation` (стандарт браузера);
если разрешение не дано — используется точка по умолчанию (центр Москвы). В боте геопозиция
запрашивается кнопкой `requestGeoLocation` в профиле.

UX-состояния реализованы для всех критичных экранов:
- **loading** — скелетоны/спиннеры при загрузке;
- **success** — подтверждение записи, добавление напоминания/избранного, сохранение оценки;
- **empty** — «Ничего не найдено. Попробуйте увеличить радиус или изменить время»;
- **error** — «Не удалось получить список занятий. Попробуйте ещё раз»;
- **retry** — кнопка «Повторить» на ошибках;
- **disabled** — слоты без свободных мест, повторное «Записаться», повторная оценка того же слота;
- **validation** — ошибки формы (имя, телефон, согласие, оценка 1–5).

Визуально близко к MAX: адаптивная вёрстка, touch-цели, читаемая типографика, единый стиль.

## 11. Разделение «бот vs мини-приложение»

- **Мини-приложение** — там, где нужен «экран»: поиск по карточкам, расписание, формы (UI-плотные задачи).
- **Бот** — «облегчённые» действия и проактивность: старт, кнопка перехода, быстрый ответ «Мои записи», напоминания.

## 12. Модель данных

Сущности (реализованы в `shared/src/types.ts` и `backend/app/models.py`, SQLAlchemy 2.0):

- **User** — id, name, city, district, ageCategory, preferredSports, preferredTime, latitude, longitude, createdAt, updatedAt.
- **Sport** — id, name, category, emoji.
- **SportFacility** — id, name, type, address, city, district, latitude, longitude, description, source, sourceUpdatedAt.
- **Activity** — id, facilityId, sportId, type, title, description, ageCategory, skillLevel, price, priceNote, organizer, contact, status.
- **Coach** — id, organizerId, name, sportId, bio (управляется организатором в админке, привязывается к слотам).
- **ScheduleSlot** — id, activityId, date, startTime, endTime, capacity, coach, coachId, status (плюс вычисляемые state/seatsFree).
- **Registration** — id, userId, slotId, name, phone, status, createdAt, canceledAt.
- **Rating** — id, userId, slotId, activityId, coachId, coachName, activityScore, coachScore, comment; уникальность (userId, slotId).
- **Favorite** — id, userId, activityId, createdAt.
- **Reminder** — id, userId, slotId, remindAt, sent, createdAt.
- **Event** — id, userId, name, payload, createdAt.
- **Organizer** — id, login, password_hash, name, createdAt.
- **AdminSession** — id, organizerId, token (opaque, случайный из БД), expiresAt.

Статусы: ActivityType `section/place/training/competition`, AgeCategory `child/teen/adult/senior/any`,
SkillLevel `beginner/intermediate/pro/any`, SlotState `open/full/cancelled/past/closed`,
RegistrationStatus `confirmed/cancelled`.

## 13. Архитектура решения

**MAX Bot (TS) → Mini App (React) → Backend (FastAPI) → PostgreSQL 16.**

- Бэкенд хранит доменную логику в `backend/app/{db,models,database,admin,auth,main}.py`;
  хранилище — PostgreSQL (SQLAlchemy 2.0), схема создаётся автоматически при старте,
  демо-данные сидируются при первом запуске.
- Админ-панель организатора (`admin-app/`, React) общается с бэкендом по `/api/admin/*`
  с opaque-токеном (Bearer), а не JWT.
- Модель данных и контракты едины для клиентов; ошибки единообразны `{"error": {code, message}}`.
- UML-диаграммы всех путей и архитектуры — в `docs/uml/` (PlantUML).

## 14. Данные и маркировка

- Все объекты и расписания — демонстрационные, источник «Демонстрационные данные MVP».
- У каждого объекта есть `source` и `sourceUpdatedAt`; на карточках это показано пользователю.
- Механика обновления дат — относительно даты запуска (`npm run seed:backend`).
- Реальных интеграций нет; в интерфейсе ярко выделяется маркировка данных.

## 15. Пилотный запуск

- **Где:** один город → один-два района → ограниченный набор партнёрских организаций (5–10).
- **Для кого:** взрослые 25–45 лет из выбранных районов.
- **Данные:** демо-набор + расписания организаций-партнёров в согласованном формате.
- **Владелец процесса:** команда хакатона + пилотный партнёр (спортивный клуб/организация).
- **Канал привлечения:** чат-бот MAX (поиск в каталоге MAX, кнопка в боте), соцсети партнёра.
- **Регистрация:** через мини-приложение; организатор видит записи через админ-панель
  (`/api/admin/*`, регистрации по активности).
- **Метрики:** конверсия, completion rate, time to registration, error rate, repeat usage.
- **Что после пилота:** анализ метрик → расширение на другие районы и организации → подключение
  официальных источников данных (Единый календарный план, реестры объектов спорта).

## 16. Масштабирование

**Ядро (не меняется):** проблема, UX, сценарий поиска, карточка, расписание, регистрация,
модель данных, API-контракт, архитектурный принцип.

**Переменная часть (адаптируется):** город, организации, объекты, справочники, источники,
интеграции, региональные правила, расписание, роли организаторов.

| Для следующей территории | Что переносится | Что адаптируется | Риски |
|---|---|---|---|
| Новый город | Всё ядро, код, seed-структура | Гео-точка по умолчанию, район, справочники | Данные о реальных объектах |
| Региональная сеть клубов | API, регистрация, напоминания | Расписания, цены, организаторы | Интеграция с их системами |
| Масштабнее (регионы) | Всё ядро | Региональные правила, источники | Согласование данных |

Путь тиражирования: пилот → один район → город → регион. Для каждого шага указываются данные,
интеграции и партнёры, а не просто «расширение на Россию».

## 17. Демо-справка

- Точка по умолчанию: центр Москвы (55.7558, 37.6173).
- Геолокация: в мини-приложении — `navigator.geolocation`, в боте — кнопка `requestGeoLocation`
  в профиле; без неё поиск идёт от точки по умолчанию.
- Для полного флоу нужен открытый слот — в seed всегда есть свободные места.
- Edge-кейсы для демонстрации: заполненный слот (плавание «день+1» 19:00), отменённый слот (волейбол «день+2» 19:00).
- Бот работоспособен без токена (режим ожидания), но напоминания требуют `MAX_BOT_TOKEN` и реального бота MAX.
- Админка организатора: `http://localhost:8081`, демо-вход `admin` / `admin123`.
